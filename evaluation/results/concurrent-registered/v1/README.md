# 实际注册模型并发实验 v1

基于 eff629a 和冻结 concurrent-v1：新采集的实际本地 Compose 观测，每批共享一次采集，经 Gateway 回放给独立事件；同一隔离 PostgreSQL 队列、注册表、官方检查点、Evidence 与报告。不是实时采集吞吐实验，没有故障注入或干净正常控制声明。

| 指标 | 2 路批次 | 4 路批次 |
| --- | ---: | ---: |
| 实际调查处理器峰值 | 2 | 4 |
| 一次完成的队列任务 | 2/2 | 4/4 |
| 工作流结果 | 2 FAILED | 4 HUMAN_HANDOFF |

| 进程 CPU 时间 | 9781ms | 11312ms |
| Python 跟踪堆峰值 | 4739794 bytes | 4758515 bytes |
| 实际模型调用（不含预检） | 8 | 10 |
| 领取等待，逐例 ms | 440,488 | 322,360,287,248 |

另有 3 次独立合成注册预检，总实际请求 21 次，均保留 provider 用量：输入 83241、输出 6923 token。实际账单未知。注册 SQL 调用表有 18 条，但其 token 字段仍缺失，精确用量来自按请求绑定的原始 provider 事件，不能把 SQL 缺失填为零。

六个事件、九份报告、36 条 Evidence/Artifact、17 次声明引用的归属和内容哈希核验通过。两条回滚证据拒绝审计，审批及执行表为空。队列完成不是诊断正确或恢复成功；四次人工接手也没有真人操作。反例、报告、检查点和每个失败结果均保留。

批次资源只覆盖本地工作流，不包含观测采集、预检、数据库/容器或模型服务端。逐例 elapsed 包含准备与队列屏障等待；共享模式没有执行重复领取探测，所以没有伪造 second_claim_count=0。CPU 为进程累计时间，堆不是总 RAM。各批只测一次且模型工作量不同，不能按两行耗时算提效、线性扩展或生产容量。
