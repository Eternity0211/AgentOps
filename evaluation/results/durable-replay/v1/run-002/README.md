# 重规划与并行续跑补充验证

14 项真实 PostgreSQL 组合测试通过，使用实际注册表、证据/报告/追踪、任务租约和官方检查点；模型与工具响应均是受控替身，不是真实 DeepSeek 质量测评。

11 个注册工作流完成，其中 10 个包含工作进程替换。两项重规划替换均断言总模型调用 4 次、工具调用 3 次、可解析证据 3 条，第一轮反馈及证据保留。并行波中一个查询已完成、另一个尚未发出的场景最终仍为 2 次模型、2 次工具调用。

另一个场景中，第二个查询已经发出但结果未知：三次任务尝试后进入 DEAD_LETTER，模型调用保持 1 次、工具调用保持 2 次，未宣告诊断或恢复成功。FAILED/CANCELLED 的旧尝试及时间、错误码保留在进度 schema 1.1.0 的有界历史中；默认记录器仍禁止终态变更，测试组合显式允许两次重试。进度不构成执行授权。

初次并行续跑测试确实失败，随后修复；另一次失败来自测试把既有队列终态误写成 FAILED，已按实际 DEAD_LETTER 契约修正。探索记录单独保留且未记录精确源码绑定，不作为最终验收证据。最终记录去除了机器名；测试时间包含环境开销，不能用于 MTTR 或人工收益。
